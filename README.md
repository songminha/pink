# cafe_scout — 네이버 카페 보험 제휴 '빈틈' 탐색기

대형 네이버 카페 목록을 돌면서 **보험 제휴(스텝·배너·협력업체) 흔적이 없는 카페**를 골라냅니다.
결과는 1차 선별용입니다. `미입점 후보`로 나온 카페만 직접 들어가서 확인하세요.

## 무엇을 보나

| 영역 | 수집 위치 | 판정 근거 | 점수 |
|---|---|---|---|
| A 메뉴판 | 카페 왼쪽 메뉴 이름 | `보험`, `보장분석`, `실손` 등이 들어간 독립 게시판 | 게시판당 3 |
| B 공지 | 대문/전체공지 + `공지사항` 게시판 글 제목 | 제휴+보험 → 3, 보험만 → 2, 제휴만(`협력업체 모집` 등) → 1 | |
| C 내부검색 | `보험스텝`, `공식보험`, `제휴보험` 검색 결과 제목 | 공지/고정글 → 2, 일반글 → 1 | |

판정 결과는 다음 중 하나입니다.

- **입점 확인**: 점수 3 이상
- **입점 의심(수동확인)**: 점수 1~2. 대부분 업종이 적히지 않은 `협력업체` 공지입니다.
- **미입점 후보(블루오션)**: A·B·C를 모두 수집했고 근거가 하나도 없음
- **판정 보류**: 근거는 없지만 일부 영역을 읽지 못함(`수집실패_영역` 열 참고). 블루오션으로 단정하지 않습니다.
- **수집 실패**: 카페 접속 자체가 실패함. 다음 실행 때 다시 시도합니다.

`4대보험`, `고용보험`, `건강보험료` 같은 정보성 게시판은 오탐이므로 제외합니다.
키워드는 `cafe_scout/keywords.py`에서 바꿀 수 있습니다.

## 설치

```bash
python -m pip install -r requirements.txt
```

크롬이 설치되어 있어야 합니다. Selenium 4.6 이상은 크롬 버전에 맞는 드라이버를 자동으로 받으므로 `webdriver_manager`는 필요 없습니다.

## 사용법

1. 카페 목록 CSV를 만듭니다. 헤더는 `카페명,카페ID`이고, 카페ID 칸에 카페 주소를 그대로 붙여 넣어도 됩니다. 형식은 `cafes.sample.csv`를 참고하세요. 샘플에 든 ID는 예시일 뿐입니다.
2. 실행합니다.

```bash
python -m cafe_scout cafes.csv
```

결과 파일은 두 개입니다.

- `카페_보험제휴_조사결과.csv`: 전체 결과와 근거 (엑셀에서 바로 열림)
- `보험_미입점_카페_리스트.csv`: `미입점 후보`만 추린 목록

### 주요 옵션

| 옵션 | 설명 |
|---|---|
| `--headless` | 브라우저 창을 띄우지 않습니다. 창을 띄우는 기본 모드보다 캡차가 뜰 가능성이 조금 높습니다. |
| `--min-delay 3 --max-delay 6` | 페이지 요청 사이에 무작위로 기다릴 시간(초) |
| `--cafe-pause 8 15` | 카페 하나를 끝낸 뒤 추가로 쉴 시간(초) |
| `--limit 20` | 이번 실행에서 처리할 카페 수. 하루에 나눠 돌릴 때 씁니다. |
| `--profile-dir ./chrome-profile` | 로그인해 둔 크롬 프로필을 사용합니다. 회원공개 메뉴까지 보려면 필요합니다. |
| `--fresh` | 기존 결과를 지우고 처음부터 다시 조사합니다. |

**이어하기가 기본입니다.** 같은 명령을 다시 실행하면 이미 조사한 카페는 건너뜁니다.
캡차나 로그인 화면이 감지되면 IP 차단을 피하려고 즉시 멈춥니다. 몇 시간 뒤 다시 실행하면 그 지점부터 이어서 진행합니다.

카페 하나당 요청은 약 5회(메인, 공지사항, 검색 3회)입니다. 기본 대기 시간 기준으로 카페당 30~45초가 걸립니다.

## 원본 가이드 코드와 달라진 점

- **URL 오류 수정**: 원본은 `https://naver.com{id}`로 접속해 실제 카페에 들어가지 못했습니다. 지금은 `https://cafe.naver.com/{id}`로 접속합니다.
- **오탐 감소**: 원본은 대문 iframe 전체 텍스트에서 `보험`을 찾았습니다. 그래서 일반 회원 글 제목에 `보험`이 한 번만 있어도 '입점 완료'로 잘못 판정됐습니다. 지금은 메뉴 이름, 공지 제목, 검색 결과로 나눠서 점수를 매깁니다.
- **실제 메뉴판 확인**: 왼쪽 메뉴는 `cafe_main` iframe 밖에 있어서 원본 코드로는 읽을 수 없었습니다. 지금은 바깥 문서와 iframe을 모두 수집합니다.
- **신·구 화면 모두 지원**: 구버전(iframe)과 신버전(`/f-e/cafes/...`) 화면을 같은 방식으로 처리합니다. CSS 선택자 대신 링크 주소 패턴(`menuid=`, `/menus/`, `articleid=`, `/articles/`)으로 메뉴와 게시글을 구분하기 때문입니다.
- **영역 B·C 구현**: 원본에는 설명만 있던 공지 탐색과 내부 검색을 실제로 구현했습니다.
- **오류를 블루오션으로 처리하지 않음**: 수집에 실패한 영역이 있으면 `판정 보류`로 표시합니다.

## 테스트

```bash
python -m pytest -q
```

- `tests/test_analyzer.py`: 키워드 판정과 점수 계산을 테스트합니다.
- `tests/test_crawler_local.py`: 가짜 카페 페이지를 로컬 서버에 띄우고 Selenium 수집 흐름을 검증합니다(iframe 전환, 신·구 화면, 캡차 감지). 크롬이 없으면 건너뜁니다.

## 한계와 주의

- **실제 네이버 화면에서는 아직 검증하지 않았습니다.** 개발 환경에서 네이버 접속이 막혀 있었습니다. 처음에는 `--limit 3`으로 몇 곳만 돌려 보고 결과 CSV의 근거 열이 제대로 채워지는지 확인하세요.
- 수집실패 영역이 C로만 나오면 내부 검색 주소 형식이 바뀌었을 가능성이 큽니다. 기본값은 구버전 검색(`ArticleSearchList.nhn`, EUC-KR)입니다. `CafeCrawler(search_url_template=...)`로 바꿀 수 있습니다.
- 이미지 배너 광고(텍스트 없는 대문 이미지)는 잡지 못합니다. 후보 카페의 대문은 직접 확인하세요.
- 공개된 메뉴와 공지 제목만 읽고, 회원 개인정보는 수집하지 않습니다. 대량·고속 수집은 네이버 이용약관에 어긋나고 차단 대상이 될 수 있습니다. 소량으로 천천히 돌리세요.
